# 政务安全前端

面向政务大模型安全评测与在线防护的综合控制台。前端已经接入 `red_blue` 红蓝对抗流程、`safe_guard` 输入输出护栏、政策事实一致性校验，以及 Qwen3-8B 与 TinyR1-Safety-8B 双模型服务。

## 页面结构与已实现功能

- 工作台：明确区分在线防护与红蓝评测，两条流程独立运行，共用模型、政策证据、检测器和人工复核能力。
- 实时检查：依次执行输入检查、生成前政策检索、Qwen回答生成、输出检查、TinyR1安全裁判和RAG事实复核；结果以六步Trace和可展开证据展示。
- 护栏审计：保存回答来源、阶段判定、证据覆盖、最终响应和发布状态。
- 批量检查：直接选择 `safe_guard` 数据集，运行独立护栏批测；支持安全停止、历史任务切换和按原配置重新运行，并分别统计攻击防护率、正常放行率和正常误阻断率，结果可导出 CSV/JSON。
- 策略与知识：查看护栏规则、模型依赖、RAG政策单元和证据来源。
- 红蓝对抗：支持单轮评测和进化闭环，展示实时步骤、运行结果与检测器版本。
- 运行分析：比较基线与候选运行，查看攻击成功率、防御成功率、代次和策略分布。
- 结果与追踪：按运行筛选完整 Trace，查看 Seed、攻击变体、蓝队原始输出、结构化判定和独立评测；运行分析从结果页按需进入。
- 风险与复核：在同一工作区切换风险台账和人工复核。攻击成功、正常样本误报，以及蓝队或独立评测置信度低于 `0.7` 的结果自动进入优先待办；普通记录仍可从 Trace 发起按需复核。
- 资源配置：集中检查任务服务、结果库和模型端点，并按需进入政策知识、评测数据集和检测器版本页。服务地址会在本机浏览器中保留。

页面只展示工作空间中的真实文件、数据库记录和模型状态。缺少正式政策来源或可选增强模型时，会明确显示为测试证据或可选扩展，不使用模拟结果代替。

刷新采用部分降级策略：单个非核心接口失败时，该分区保留上一次成功数据并标出尚未更新的内容；任务服务临时断开时保留最后一次完整结果，恢复连接后可以直接继续。

## 本地运行

后端服务默认只绑定 `127.0.0.1:8788`：

在项目根目录启动服务：

```bash
python -m pip install -e '.[service]'
rb-platform --config config/example.yaml serve-api
```

启动前端：

```bash
npm install
npm run dev
```

浏览器访问 `http://localhost:3000`。Qwen与TinyR1使用OpenAI兼容接口，当前配置分别连接 `127.0.0.1:8000/v1` 和 `127.0.0.1:8001/v1`；模型可以运行在本机，也可以通过SSH端口转发连接服务器。

## 交付检查

```bash
npm run typecheck
npm run lint
npm test
```

高级事实校验器的现有索引包含196个政策单元、1176个检索片段，并区分正式来源与测试/种子证据；未启用高级索引时，界面会如实显示轻量政策库的实际数量。进入生产前仍需持续扩充经审核的正式政策覆盖，建立政策更新、失效和权限管理机制。语义向量模型和专用输出安全模型属于可选增强；停止后继续运行和SSE事件流尚未接入。HTTPS发布页面不能直接访问用户电脑上的HTTP模型服务，真实测试应在localhost环境执行。
